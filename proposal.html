Compiler2 Runtime Transport Spine

The current plan for replacing runtime-layout translation with one pure transport information-flow authority.

Status: this document supersedes the older runtime-value-demand proposal that ended at RuntimeParamLayout, RuntimeInputLayout, and RuntimeValueLayout. Runtime demand is still the right pre-spine solver. Recursive runtime layout is not the destination. The implementation strategy is now explicit: first trash-prefix the doomed vocabulary, then build the clean flow graph independently beside the old path, then cut consumers over and delete the old path. The short canonical statement is outline.md.

1. Goal, signal, strategy

Goal

Compiler2 has one runtime transport shape for every transported value. It is built once into a root-scoped TransportPlan using shared interned descriptors. Every downstream layer reads that plan and indexes fact tables; no layer rebuilds or translates it.

Signal

No function below plan construction walks RuntimeDemand, TrashRuntimeValueLayout, TrashReturnAbi, or TrashDeliveredShape to emit another shape. Tests assert the plan and fact-table projections.

Strategy

Use the Output Contract Loop. Build the clean flow graph alongside the old path from semantic evidence only; use the old path as behavior oracle and removal inventory, never as an adapter. Then cut consumers over and delete the trash-prefixed authority.

Core rule: semantic evidence is not representation obligation. Runtime demand discovers what must move. The transport plan records the settled shape. Published boundary contracts, interpreter, native, and codegen details are columns keyed by that plan.

2. The law

Shape = Nothing | Lane(LaneId) | Tuple(Vec<ShapeId>) | Callable(CallableId)
ItemMeaning
ShapeId An interned shape descriptor. Like the type interner, recursive children are ids. Sharing scope follows descriptor key stability; root-scoped validity lives in TransportPlan.
LaneId One non-callable transported leaf, usually keyed by settled Ty or a stable transport class. Boundary and codegen representation are contextual facts, not global lane identity.
CallableId A callable identity. Its descriptor may include immutable key material. Locality, direct surfaces, and published boundary contracts are facts keyed by this id. Ordered capture lane payload is descriptor key material when it distinguishes callable identity, and is also exposed as a consumer fact.
BoundaryId One published callable contract. A callable may have zero or more boundary contracts; publication context is a fact, not a shape variant.
Nothing The only post-spine spelling of "not transported". RuntimeDemand::Ignore exists before the spine and becomes Nothing exactly once.
Some facts stay outside the spine. Divergence is is_empty(return_ty), not a shape node. ExecutableNeed is the coarse pre-spine seed, not a post-spine shape key. ValueId maps to ShapeId; it is not embedded in the shape. RootId owns a closure/query over symbols; it is not automatically part of shareable descriptor identity.

3. Required first move

Before any transport-spine or parallel-flow implementation work, rename the doomed vocabulary with an explicit trash marker. This is not cosmetic. It is a compaction-resistant guardrail: future work should have to type an ugly name if it tries to wire doomed architecture back in.

RuntimeValueLayout -> TrashRuntimeValueLayout
RuntimeInputLayout -> TrashRuntimeInputLayout
RuntimeParamLayout -> TrashRuntimeParamLayout
RuntimeLane -> TrashRuntimeLane
ReturnAbi -> TrashReturnAbi
DeliveredShape -> TrashDeliveredShape
NativeDemandAbi -> TrashNativeDemandAbi
RealizedValue -> TrashRealizedValue
BackendValue -> TrashBackendValue

Apply the same rule to shape-translation helpers where they are transport authority.

Scope of the first ticket: pure rename plus required docs/test-name updates. No behavior work, no aliases, no compatibility layer, no bridge from the old names to the new model, and no ShapeId / BoundaryId / TransportPlan implementation. If something cannot be renamed cleanly, create a follow-up ticket before closing the guardrail ticket.

4. Current disease

The current compiler2 path already moved in the right direction, but the remaining authority is still recursive layout, not a stable spine.

RuntimeDemand
  -> RuntimeValueLayout
  -> abi_reprs / lane_tys
  -> ReturnAbi / boundary projection
  -> NativeBody return_layout / resume_layouts / capture_layouts
  -> RealizedValue { layout, lanes }
  -> DeliveredShape / NativeCodegenSurface
  -> local ArgRepr and continuation-shape decisions

That is the disease: one shape vocabulary keeps being walked to emit another. Each translation creates a new authority and a new place for facts to drift.

Current authority leakWhy it is wrong
RuntimeValueLayout It is a recursive post-demand shape copy. It should become ShapeId plus fact-table reads.
DeliveredShape It is a codegen-local delivery shape derived from layout or a boundary projection.
RealizedValue.layout It mirrors the transport tree with different leaves. Runtime values should be shape refs plus lane bundles.
ArgRepr::from_ty Compiler2 transport lanes should read published lane/codegen facts, not rederive reprs from type locally.

5. Target model

The target has shared descriptor interners plus a root-scoped plan built after semantic closure and runtime demand settle.

SemanticClosed(root)
  -> RuntimeDemandClosure
  -> shared descriptor interners
       ShapeId -> Shape
       LaneId -> lane descriptor
       CallableId -> callable descriptor
       BoundaryId -> boundary descriptor
  -> TransportPlan(root)
       membership: executable symbols
       positions: TransportPosition -> ShapeId
       lane facts: LaneId -> ty/transport class
       callable facts: CallableId -> direct surfaces/captures/boundary ids
       boundary facts: BoundaryId -> published contract
       seam facts: (id, seam) -> codegen representation

Downstream artifacts carry references into this plan. They do not copy the tree.

SeamReadsDoes not do
Artifact Demand closure; builds the independent plan and fact tables once. Does not publish recursive layout as a second shape authority.
Published boundary contract Boundary contract columns keyed by BoundaryId, CallableId, and shared shape ids. Does not reshape internal returns, captures, or resumes.
Backend/interpreter Shape refs and lane bundles. Does not rebuild tuple/callable structure in value variants.
Native Shape refs, lane spans, callable ids, and published boundary ids. Does not materialize callable boundaries from local capture types.
Codegen Published seam-specific codegen facts. Does not derive delivery shape, repr, continuation arity, or tuple-return plans locally.

6. Fact tables

The exact Rust names can differ. The important property is that shared structure lives in descriptor interners and root-specific validity/details live in plan tables.

Implementation status after fz-hwn.20.4: src/compiler2/transport.rs defines the root-independent ids, descriptors, transport symbols, TransportPosition, TransportInterners, and TransportStore. World owns one TransportStore. DeriveTransportPlan(root) now populates root-scoped positions plus CallableId and BoundaryId fact tables from settled semantic evidence. Boundary contracts preserve callable leaves as one published value lane and tuple returns as recursive boundary-return contracts, not flat lane lists. Boundary returns are published per surface, so one callable used at two surfaces has two contracts when those return transports differ. Callable capture shapes read settled callee input demand when a resolution exists; boundary demand is only the fallback for unresolved or opaque capture obligations. Capture lane facts preserve payload order and duplicate lanes. Direct-call surfaces and first-class boundary publication are independent facts, so one callable can have both. DeriveTransportPlan(root) is scheduled as a side-output of settled semantic closure, but materialization, backend, native, and codegen do not wait on or consume it yet. Codegen seam facts are deliberately empty until fz-hwn.20.5. The transport calculator reads RuntimeDemand/CallableDemand, not the old callable-materialization inventory, and no old Trash* layout is translated into descriptors.

}

  callable: CallableId,

  published_capture_lanes: Vec<LaneId>,

  published_return_lanes: Vec<LaneId>,
}

CallableId is not LocalCallableId. Local/direct/first-class behavior is a fact about the callable, not a different identity class.

ValueId is not LaneId and not ShapeId. A value, slot, return, capture, or continuation payload position maps to a shape; the shape itself stays interned and independent of semantic value identity.

8. Required changes

8.1 Trash-prefix the doomed vocabulary before any other work

This is fz-hwn.19.7. It blocks the parallel flow-graph epic and the still-open symptom tickets that touch this vocabulary.

8.2 Build the independent flow graph beside the old path

This is fz-hwn.20. Use the Output Contract Loop: pin the worked example, introduce shared interners and symbols, derive TransportPlan(root) from semantic evidence only, publish callable/boundary facts, publish seam-specific codegen facts, then prove the plan with telemetry/tests. The old path can keep behavior running, but it must not feed the new plan.

8.3 Accept the handoff and cut consumers over

This starts fz-hwn.19. If a consumer reads the new plan, the matching old authority must disappear from that seam in the same commit or remain behind an explicit later cutover ticket. No compatibility bridge is committed.

Remove:
  TrashRuntimeValueLayout
  TrashRuntimeInputLayout
  TrashRuntimeLane
  runtime_value_layout_from_demand
  runtime_input_layout_from_demand
  local_callable_layout as a layout builder

Replace with:
  TransportPlan(root)
  TransportPosition -> ShapeId tables
  LaneId facts
  CallableId facts
  BoundaryId facts
  seam-specific codegen facts

8.4 Make callable materialization consume CallableId / BoundaryId facts

First-class callable entries, native boundaries, identity fns, capture lanes, boundary boxing, and direct-callable transport are all facts keyed by CallableId. Codegen never re-selects a boundary from function plus capture types.

8.5 Collapse runtime values to shape refs plus lanes

Backend/interpreter/native values carry a ShapeId and lane bundle/span. Tuple fields are views through child shape ids. Direct callable invocation reads target and capture facts from CallableId.

8.6 Make codegen consume seam facts only

Codegen reads seam facts. It does not decide transport shape, infer continuation result shape, derive reprs from type, or inspect raw IR to rediscover tuple return delivery.

10. Checks

10.1 Behavior

  • Quicksort keeps tuple-field return/resume transport without tuple allocation.
  • Ignored callable constructors publish no callable entry, native boundary, or closure allocation.
  • Direct captured lambda calls pass capture lanes directly without heap closure materialization.
  • Direct callable values cross return/resume seams structurally.
  • Escaped callables publish exactly the required first-class boundary.
  • Opaque callable calls use explicit boundary facts, not type recovery.
  • Backend interpreter and native JIT consume the same transport facts after cutover.

10.3 Telemetry

Prefer event-level assertions over brittle dumps where the event expresses the invariant. fz-hwn.20.3 turns on the production-boundary assertion in src/compiler2/transport_contract_test.rs and adds targeted fixtures for ignored returns, tuple return/resume sharing, and direct-callable return/resume sharing. fz-hwn.20.4 adds worked source fixtures for callable/boundary facts: unused callable constructors publish no boundary, direct lambda calls stay direct-only, escaped lambdas publish exactly one first-class boundary, opaque callable inputs publish an explicit boundary, same-surface callables remain distinct when their capture obligations differ, callable arguments publish one boundary lane, tuple callable returns publish recursive tuple return contracts, duplicate same-typed captures remain duplicate ordered payload lanes, multi-surface callable boundaries publish return contracts per surface, directly recursive tuple returns share return/resume shapes, a directly-called callable that also escapes keeps both direct surfaces and boundary ids, and a callable captured only for direct use is not upgraded into a first-class boundary.

The landed derivation boundary is explicit: callable and boundary facts are derived by the new transport calculator from settled demand, lowered callable use sites, local callable producers, captures, callsite summaries, and settled type evidence. The old layout, native boundary inventories, and callable-entry materialization are not inputs to the transport plan; the new calculator does not read CallableMaterialization.

Conclusion

The smallest correct model is not a callable patch and not a better recursive layout. It is shared descriptor interners plus root-scoped transport plans. Runtime demand discovers what must move. The plan records the shape once. Every later layer reads facts.

Acceptance contract: no runtime object, published boundary lane, callable entry, native callable boundary, closure allocation, continuation payload, or codegen delivery shape exists unless a settled TransportPlan fact requires it.

Compiler2 Runtime Transport Spine

The current plan for replacing runtime-layout translation with one stable transport shape authority.

Status: this document supersedes the older runtime-value-demand proposal that ended at RuntimeParamLayout, RuntimeInputLayout, and RuntimeValueLayout. Runtime demand is still the right pre-spine solver. Recursive runtime layout is not the destination. The short canonical statement is outline.md.

1. Goal, signal, strategy

Goal

Compiler2 has one runtime transport shape for every transported value. It is built once after demand settles. Every downstream layer reads that shape and indexes fact tables; no layer rebuilds or translates it.

Signal

No function below spine construction walks RuntimeDemand, RuntimeValueLayout, ReturnAbi, or DeliveredShape to emit another shape. Tests assert the spine and fact-table projections.

Strategy

Work data-model-up. Pin current behavior, introduce the spine, replace recursive layout as authority, collapse backend/native value mirrors, then make codegen consume published lane facts only.

Core rule: semantic evidence is not representation obligation. Runtime demand discovers what must move. The transport spine records the settled shape. ABI, boundary, interpreter, native, and codegen details are columns keyed by that spine.

2. The law

Shape = Nothing | Scalar(ScalarId) | Tuple(Vec<ShapeId>) | Callable(CallableId)
ItemMeaning
ShapeId A node in the settled root-scoped transport spine.
ScalarId A scalar leaf. It is rooted in ValueId when there is a body value, or in a stable minted leaf id for interior tuple leaves.
CallableId A callable identity. Locality, directness, captures, boundary boxing, and materialization are facts keyed by this id.
Nothing The only post-spine spelling of "not transported". RuntimeDemand::Ignore exists before the spine and becomes Nothing exactly once.
Two facts stay outside the spine. Divergence is is_empty(return_ty), not a shape node. ExecutableNeed is the coarse pre-spine seed, not a post-spine shape key.

3. Required first move

Before any transport-spine implementation work, rename the doomed vocabulary with an explicit trash marker. This is not cosmetic. It is a compaction-resistant guardrail: future work should have to type an ugly name if it tries to wire doomed architecture back in.

RuntimeValueLayout -> TrashRuntimeValueLayout
RuntimeInputLayout -> TrashRuntimeInputLayout
RuntimeLane -> TrashRuntimeLane
DeliveredShape -> TrashDeliveredShape
NativeDemandAbi -> TrashNativeDemandAbi

Apply the same rule to recursive value mirrors and shape-translation helpers where they are transport authority.

Scope of the first ticket: pure rename plus required docs/test-name updates. No behavior work, no aliases, no compatibility layer, no bridge from the old names to the new spine. If something cannot be renamed cleanly, create a follow-up ticket before closing the guardrail ticket.

4. Current disease

The current compiler2 path already moved in the right direction, but the remaining authority is still recursive layout, not a stable spine.

RuntimeDemand
  -> RuntimeValueLayout
  -> abi_reprs / lane_tys
  -> ReturnAbi boundary projection
  -> NativeBody return_layout / resume_layouts / capture_layouts
  -> RealizedValue { layout, lanes }
  -> DeliveredShape / NativeCodegenSurface
  -> local ArgRepr and continuation-shape decisions

That is the disease: one shape vocabulary keeps being walked to emit another. Each translation creates a new authority and a new place for facts to drift.

Current authority leakWhy it is wrong
RuntimeValueLayout It is a recursive post-demand shape copy. It should become ShapeId plus fact-table reads.
DeliveredShape It is a codegen-local delivery shape derived from layout or boundary ABI.
RealizedValue.layout It mirrors the transport tree with different leaves. Runtime values should be shape refs plus lane bundles.
ArgRepr::from_ty Compiler2 transport lanes should read published scalar/codegen lane facts, not rederive reprs from type locally.

5. Target model

The transport plan is root-scoped and built after semantic closure and runtime demand settle.

SemanticClosed(root)
  -> RuntimeDemandClosure
  -> TransportSpine(root)
       shapes: ShapeId -> Shape
       executable roots: ExecutableKey -> executable transport facts
       scalar facts: ScalarId -> ty/repr/codegen lane
       callable facts: CallableId -> target/captures/materialization/boundary facts

Downstream artifacts carry references into this plan. They do not copy the tree.

SeamReadsDoes not do
Artifact Demand closure; builds the spine and fact tables once. Does not publish recursive layout as a second shape authority.
Boundary ABI Boundary fact columns keyed by ShapeId / CallableId. Does not reshape internal returns, captures, or resumes.
Backend/interpreter Shape refs and lane bundles. Does not rebuild tuple/callable structure in value variants.
Native Shape refs, lane spans, callable ids, and published boundary ids. Does not materialize callable boundaries from local capture types.
Codegen Published codegen lane facts. Does not derive delivery shape, repr, continuation arity, or tuple-return plans locally.

6. Fact tables

The exact Rust names can differ. The important property is that structure lives in one spine and layer-specific details live in tables.

TransportSpine {
  shapes: Vec<Shape>,
  executable: HashMap<ExecutableKey, ExecutableTransport>,
  scalars: HashMap<ScalarId, ScalarTransportFacts>,
  callables: HashMap<CallableId, CallableTransportFacts>,
}

ExecutableTransport {
  input_shapes: Vec<ShapeId>,
  return_shape: ShapeId,
  resume_shapes: Vec<Option<ShapeId>>,
  entry_capture_shapes: Vec<Vec<ShapeId>>,
}

ScalarTransportFacts {
  ty: Ty,
  abi_repr: AbiValueRepr,
  codegen_repr: ArgRepr,
}

CallableTransportFacts {
  target: ExecutableKey,
  capture_shapes: Vec<ShapeId>,
  capture_lanes: Vec<LaneFact>,
  materialization: CallableMaterialization,
  boundary: Option<CallableBoundaryFact>,
}

CallableId is not LocalCallableId. Local/direct/first-class behavior is a fact about the callable, not a different identity class.

8. Required changes

8.1 Trash-prefix the doomed vocabulary before any other work

This is fz-hwn.19.7. It blocks the rest of the spine plan and the still-open symptom tickets that touch this vocabulary.

8.2 Pin contracts before changing the model

Tests must state the desired authority before the cutover: scalar transport, ignored values, tuple-field returns/resumes, direct callable returns/resumes, escaped callable boundaries, opaque callable boundaries, backend interpreter parity, and native JIT delivery.

8.3 Replace recursive layout in one cutover

This is the painful step. If old and new models both survive a commit, we have created the bridge we are trying to delete.

Remove:
  RuntimeValueLayout
  RuntimeInputLayout
  RuntimeLane
  runtime_value_layout_from_demand
  runtime_input_layout_from_demand
  local_callable_layout as a layout builder

Replace with:
  ShapeId-backed executable transport facts
  ScalarId facts
  CallableId facts
  lane tables

8.4 Make callable materialization a CallableId projection

First-class callable entries, native boundaries, identity fns, capture lanes, boundary boxing, and direct-callable transport are all facts keyed by CallableId. Codegen never re-selects a boundary from function plus capture types.

8.5 Collapse runtime values to shape refs plus lanes

Backend/interpreter/native values carry a ShapeId and lane bundle/span. Tuple fields are views through child shape ids. Direct callable invocation reads target and capture facts from CallableId.

8.6 Make codegen consume facts only

Codegen reads lane facts. It does not decide transport shape, infer continuation result shape, derive reprs from type, or inspect raw IR to rediscover tuple return delivery.

9. Removal map

RemoveReplacement
RuntimeValueLayout family ShapeId plus spine/fact-table lookups.
abi_reprs() / lane_tys() walks Lane table reads.
DeliveredShape / NativeDemandAbi Published codegen lane facts and divergence bit.
Recursive RealizedValue / BackendValue mirrors Shape ref plus lane bundle/span.
Boundary selection from capture types Settled boundary id fact attached to CallableId.
ArgRepr::from_ty for compiler2 transport Scalar/codegen lane fact keyed by ScalarId.
Shape mismatch adapters caused by local projections No adapter: both sides read the same spine facts.

10. Checks

10.1 Behavior

  • Quicksort keeps tuple-field return/resume transport without tuple allocation.
  • Ignored callable constructors publish no callable entry, native boundary, or closure allocation.
  • Direct captured lambda calls pass capture lanes directly without heap closure materialization.
  • Direct callable values cross return/resume seams structurally.
  • Escaped callables publish exactly the required first-class boundary.
  • Opaque callable calls use explicit boundary facts, not type recovery.
  • Backend interpreter and native JIT consume the same transport facts.

Conclusion

The smallest correct model is not a callable patch and not a better recursive layout. It is one transport spine plus fact tables. Runtime demand discovers what must move. The spine records the shape once. Every later layer reads facts.

Acceptance contract: no runtime object, ABI lane, callable entry, native callable boundary, closure allocation, continuation payload, or codegen delivery shape exists unless a settled spine fact requires it.

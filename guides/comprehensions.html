fz comprehensions guide

How for turns generators, filters, into: and reduce: into ordinary Enum.reduce calls.

  • 2. What for becomes

  • 4. Not built

1. Supported forms

for x <- [1, 2, 3], do: x * 2                          # [2, 4, 6]
for {:ok, v} <- results, do: v                    # elements that do not match are skipped
for x <- xs, x > 1, do: x                         # a filter keeps what it accepts
for x <- xs, y = f(x), y > 1, do: {x, y}      # a match filter binds y for what follows
for x <- xs, y <- ys, do: {x, y}                  # the inner generator runs for each outer element
for x <- xs, into: %{}, do: {x, x}               # collect through Collectable
for x <- xs, reduce: 0 do
  acc -> acc + x
end

Any enumerable can be a generator source: a list, a map (yielding {key, value} pairs) or a range. A generator pattern is any pattern; a filter is any expression, truthy unless it is nil or false.

2. What for becomes

The compiler rewrites for to calls it already handles, before decoding. Each generator opens an Enum.reduce whose accumulator threads inward.

PieceRewrite
Generator p <- e, refutable pEnum.reduce(e, acc, fn elem, acc' -> case elem do p -> STEP; _ -> acc' end end)
Generator, irrefutable p (a variable, _, _name)Enum.reduce(e, acc, fn p, acc' -> STEP end)
Filter fif f, do: STEP, else: acc
Innermost, plain[body | acc]; the outer result is Enum.reverse(result), starting from []
Innermost, into: cfun.(acc, {:cont, body}); with {init, fun} = Collectable.into(c) before and fun.(result, :done) after
Innermost, reduce: acase acc do clauses end; the start is a and the result is returned as is

3. Scope

Pattern variables are visible in later generators, filters and the body. Nothing a for binds is visible after it. The variables the rewrite introduces are generated, so they never collide with names you wrote.

4. Not built

  • uniq: true is refused at compile time: comprehension uniq: is not built.
  • Bitstring generators (<<c <- binary>>) are refused at compile time: comprehension bitstring generators are not built.

Also compile errors: into: together with reduce:, a reduce: whose do is not a list of -> clauses, a for that does not start with a generator, and any other option. Every one of these reports parse/comprehension at the for.

5. The contract

  • for is source sugar: it adds no node to the compiler beyond the rewrite in source_sugar.rs.
  • A generator whose pattern does not match an element skips it.
  • An irrefutable generator pattern gets no skip arm.
  • The plain form returns a list in generator order; into: returns the collectable; reduce: returns the accumulator.
  • uniq: and bitstring generators fail loudly.
